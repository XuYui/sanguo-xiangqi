# 棋盘几何生成器

把实物三人象棋棋盘逆向成可复用的**矢量棋盘 + 坐标数据 + 生成代码**。
`packages/core/data/board_data.json`（引擎使用的全部点位坐标）就由这个生成器产出。

```
sanguo_xiangqi_board.py   ← 生成器（改参数即可重新出图：SVG / JSON / PNG）
example_usage.py          ← 使用示例：初始布局读取、坐标换算、最近点查询、自定义局面
selfcheck.py              ← 交付物自检：SVG 合法性 / 热区 / JSON / 对称性 / 九宫 / 初始布局
preview.png               ← 位图预览（已提交，便于直接查看）
```

运行后在本目录生成（已加入 `.gitignore`，不提交）：

```
三人象棋棋盘.svg          ← 矢量棋盘（含三方棋子初始布局），1200×1200
board_data.json           ← 135 个交叉点坐标 + (势力, 列, 行) + 三方初始布局
```

依赖：Python 3.9+、Pillow（`pip install pillow`，仅用于 `preview.png`）。

与项目的关系：

* 修改几何参数后，把生成的 `board_data.json` 复制到 `packages/core/data/`，
  再运行 `npm run check`（拓扑测试会校验 135 点 / 243 边 / 15 条跨河边等结论）；
* `packages/core/data/board-empty.svg` 是在生成结果基础上加了木纹底图、去掉棋子的界面底图，
  前端用的 `apps/web/public/board*.svg` 再由 `packages/core/tools/exportWeb.ts` 从它导出。

## 初始布局（`#setup` 图层）

三家各自在自己半边按**标准象棋摆法**布子（本地坐标 `file 1..9`（自家左手起）、
`rank 1..5`（1 = 底线））：

```
rank 5: ·  ·  ·  ·  ·  ·  ·  ·  ·        · = 空点
rank 4: 兵 ·  兵 ·  兵 ·  兵 ·  兵        ← 5 枚兵
rank 3: ·  炮 ·  ·  ·  ·  ·  炮 ·        ← 2 枚炮
rank 2: ·  ·  ·  ·  ·  ·  ·  ·  ·        （九宫中心，写势力名）
rank 1: 車 馬 相 仕 帥 仕 相 馬 車        ← 底线 9 枚
```

共 `16 × 3 = 48` 枚；每方颜色不同（魏 #2563eb 蓝 / 蜀 #dc2626 红 / 吴 #2f855a 绿），
棋子字身朝向与该家其他标注一致（自家座位方向）。

* 数据在 `board_data.json` 的 `setup.layout`（通用摆法）与
  `players.<key>.initial_pieces`（含每枚棋子的模型坐标）里，可直接喂给引擎。
* 生成器顶部 `PIECE_START` 是唯一的摆法表：如果实物棋规不同（比如多子/少子、
  或三家使用不同字样），改这张表即可；`PIECE_R` / `PIECE_FONT` 控制棋子大小。
* `SHOW_SETUP = False` 可输出空棋盘。
* SVG 中棋子层是独立的 `<g id="setup">`（内含 `setup-wei/shu/wu`），
  前端可以整层隐藏/替换，也可以按 `data-*` 自行定位。

重新生成：

```bash
python sanguo_xiangqi_board.py     # 重新输出 svg / json / preview.png
python example_usage.py            # 跑一遍坐标换算示例并生成带棋子的 SVG
```

## 一、棋盘结构（从实物逆向出的结论）

三人象棋棋盘 = **一个正六边形**，由三部分拼成：

| 组成部分 | 数量 | 说明 |
|---|---|---|
| 三方地盘 | 3 | 每方 = 标准象棋的**一边**（9 列 × 5 行交叉点 = 半边棋盘） |
| 界河（楚河汉界的三人版） | 3 | 赤壁（魏｜吴）、祁山（魏｜蜀）、荆州（蜀｜吴），与史实一致 |
| 中央三角形 | 1 | 三条界河的内侧边界，三家地盘的共同前沿 |

* 六边形三条**有数字的边** = 三家的**底线**（魏在下、吴在左上、蜀在右上）；
  三条**有字母的边** = 三家的**侧翼**（魏 A-E 在左下、蜀 F-J 在右下、吴 K-O 在上）。
* 每方地盘是**扇形（keystone）**：底线是直线，越往中央越宽——
  底线 9 点间距为 `1/8` 边长，最内一行 9 点间距扩大到约 `1.7 × 1/8`。
* 每方的**行线是折线**（"^" 形，在中间一路处打折），最内一行正好穿过自家对应的
  中央三角形顶点；**列线是直线**，第 1、9 列线恰好与六边形侧翼边重合。
* 界河是四边形空带：外侧「河口」= 侧翼边中间 `1/9` 段；内侧 = 中央三角形的一条边。
* 九宫与象棋完全一致：第 4~6 列 × 第 1~3 行（3×3 点）+ 两条对角线；
  **两条对角线是折线，各自精确穿过九宫中心格点 P(5,2)**（角点 → 中心格点 → 角点）。
  注意：扇形坐标下若按「角对角直线」画，两条直线的交点会偏离中心格点约 0.023 模型单位
  （≈12 px @1200），与实物不符——实物就是过中心格点的折线。

### 数学构造（模型坐标，原点 = 棋盘中心，外接圆半径 `R = 1`，y 轴向下）

```
六边形顶点： V1(-0.5, +0.866)  V2(+0.5, +0.866)  RV(+1, 0)
             TR(+0.5, -0.866) TL(-0.5, -0.866)  LV(-1, 0)

中央三角形： 正三角形，重心 = 原点，顶点指向三家，外接圆半径 TRI_R = 0.17
             T_魏(0, +0.17)   T_吴(-0.147, -0.085)   T_蜀(+0.147, -0.085)

某一方（以魏为例）：
  第 1 行 P1[f] = lerp(V1, V2, (f-1)/8)                f = 1..9
  第 5 行端点   e1 = lerp(V1, LV, 4/9)   e9 = lerp(V2, RV, 4/9)     ← 4/9 为实测值
  第 5 行 P5[f] = 折线 e1 → T_魏 → e9 上的等分点（每臂 4 段）
  第 r 行  P[r][f] = lerp(P1[f], P5[f], (r-1)/4)          r = 1..5
  列线 f： P1[f] → P5[f] 直线段
  行线 r： 折线 P[r][1] → … → P[r][5] → … → P[r][9]（左右两半各自直线）
  九宫：   第 4~6 列 × 第 1~3 行 + 对角线 P(4,1)-P(6,3)、P(6,1)-P(4,3)

蜀、吴 = 把上面这套几何整体旋转 ±120°。
```

**实测校核**（对照片做透视校正后，在模型坐标里量）：
第 5 行端点落在侧翼边 `4/9` 处（实测 0.444）、行距沿侧翼边为 `1/9` 边长、
底线 9 点等分该边、九宫 3×3、中央三角形外接圆半径 ≈ 0.165~0.17 —— 与上面的构造一致。
（`R`、`TRI_R`、`RANK5_T`、`FLANK_DIV` 都是脚本顶部的可调参数。）

## 二、坐标约定（棋规 / 引擎用）

每方有本地坐标 `(file, rank)`：

* `file = 1..9`：从**该方自己左手边**数起（与实物棋盘印刷方向一致）；
* `rank = 1..5`：`1` = 底线，`5` 最靠中央。

实物棋盘上的行号字母 ↔ rank（字母 A–O 沿六边形顺时针排列）：

| 势力 | 行号字母（rank 1→5） | 备注 |
|---|---|---|
| 魏 | **E D C B A** | 字母写在左下侧翼边 |
| 蜀 | **J I H G F** | 写在右下侧翼边 |
| 吴 | **O N M L K** | 写在上面那条边 |

底线的数字 1–9 与 `file` 一一对应（魏从左到右 1→9；吴自 TL 顶点起 1→9；蜀自 RV 顶点起 1→9）。

`board_data.json` 结构：

```jsonc
{
  "meta":  { "files_per_player": 9, "ranks_per_player": 5, "palace": {...}, ... },
  "hexagon": { "R": 1.0, "vertices": { "V1": [...], ... } },
  "centre_triangle": { "circumradius": 0.17, "vertices": { "wei": [...], ... } },
  "rivers": { "chibi": {"text": "赤壁", "between": ["wei","wu"]}, ... },
  "players": {
    "wei": {
      "name": "魏", "rotation_deg": 0.0, "neighbours": ["wu","shu"],
      "rank_letters": ["E","D","C","B","A"],
      "points": [ { "file":5, "rank":1, "rank_letter":"E",
                    "x":0.0, "y":0.866, "palace":false,
                    "back_rank":true, "river_rank":false }, ... ]   // 45 条
    }, "shu": {...}, "wu": {...}
  }
}
```

## 三、SVG 用法

* 根元素 `1200×1200`，`viewBox="0 0 1200 1200"`，几何居中；
  `model(x,y) → svg(600 + x*S, 600 + y*S)`，其中 `S = 1200 / (2 + 2*0.17) ≈ 512.8`。
* 分组 id：`#board`（棋盘线）、`#territory-wei|shu|wu`、`#centre-triangle`、
  `#labels`（势力名）、`#rivers`、`#points`（交叉点**透明热区**）。
* **势力名（魏/蜀/吴）写在各自九宫「田字格」的正中央**（= 中心格点 P(5,2)），
  字「上」方向指向棋盘中心（自家座位方向），占格约 55%。字号见 `NAME_SIZE`。
* **棋盘外围不绘制数字 1–9 与行号字母 A–O**（按要求已删除，`SHOW_EDGE_LABELS = False`）。
  列的 1–9 与行的 E/A 等字母信息仍然完整保留在 `board_data.json` 里
  （每点带 `file` / `rank` / `rank_letter`），前端标注时可自行取用；
  若要把它们画回棋盘，把 `SHOW_EDGE_LABELS` 改成 `True` 重跑即可。
* 每个交叉点都有热区圆：`<circle id="wei-f5-r1" data-player="wei" data-file="5" data-rank="1" .../>`，
  前端可直接用 `svg.querySelector('#wei-f5-r1')` 定位落子坐标。
* 棋子叠加示例见 `example_usage.py`。
* **界河名（赤壁/祁山/荆州）按「主视角」排版**：字头一律朝上，字序按该视角的自然读向——
  赤壁沿河道向右上（赤→壁）、祁山沿河道向右下（祁→山）、荆州竖排（荆在上、州在下）。
  这与实物印刷朝向不同（实物是按各自那家的座位方向印的，在主视角下是倒的/侧躺的）。
  相关开关（生成器顶部）：
  * `RIVER_MAIN_VIEW = True` 主视角可读；`False` 恢复实物印刷朝向；
  * `RIVER_FOLLOW_BAND = True` 文字沿河道倾斜；`False` 一律水平正排（竖河道仍竖排）；
  * `RIVER_POS` 沿河道位置（0 = 河口，1 = 内侧边界），`RIVER_SIZE` 字号。
* 做可下棋的界面时，可把生成器顶部参数改为
  `SHOW_NAMES = False`（去掉势力名）或 `NAME_OPACITY = 0.35`（淡化，避免与棋子打架）。
* 文字字体：SVG 里给出了 CJK 字体栈
  （Noto/思源宋体/宋体/微软雅黑），如需完全可控可用工具把文字转成路径。

## 四、逆向过程（可复现）

1. 对照片做透视校正：以六边形轮廓拟合单应变换（5 个可见顶点，残差 ≈ 1 px），
   得到「模型空间」下的棋盘正视图。
2. 在模型空间里量测：六边形边长、底线 9 点、侧翼边 10 个交点（行距 = 1/9 边长）、
   第 5 行端点位置（4/9）、九宫位置、中央三角形尺寸、界河走向。
3. 用另一张印刷参考图交叉验证：对其做霍夫变换求出六边形六条边 → 顶点 → 相似变换，
   把生成结果叠加上去，逐条线比对吻合。

> 说明：实物棋盘的印刷存在手工误差（照片量测显示各边长度、角度有 1°~2° 的偏差，
> 三角形半径实测在 0.165~0.17 之间）。本项目输出的是**理想化、严格三重旋转对称**的版本，
> 更适合电子化使用。
